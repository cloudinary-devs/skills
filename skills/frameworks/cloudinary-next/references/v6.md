# Projects on next-cloudinary v6

Load this when the project uses `next-cloudinary` 6.x. The rest of this skill is written for v7. Where this file differs, follow this file.

## Requirements

- v6 supports Next.js 12 to 16 and React 17 to 19.
- v7 needs Next.js 16, React 18.2 or 19, and Node.js 22 or later. A project below Next.js 16 must stay on v6 (or upgrade Next.js first).
- Install v6 explicitly: `npm install next-cloudinary@6`, with a caret range in `package.json` (`"next-cloudinary": "^6.0.0"`). Without `@6`, npm installs the latest major, which refuses to install on Next.js 15 or earlier.

## Differences from the v7 guidance

| Topic | v6 behaviour |
| --- | --- |
| Server Components | No `next-cloudinary` component works in a Server Component, including `CldImage`. Put every component in a file with `'use client'`, or in a small Client Component wrapper. The URL helpers (`getCldImageUrl`, `getCldVideoUrl`, `getCldOgImageUrl`) work on the server. |
| Video player CSS | Only `next-cloudinary/dist/cld-video-player.css` exists. `next-cloudinary/cld-video-player.css` is v7 only. |
| Video player version | `CldVideoPlayer` uses Cloudinary Video Player 1.11.1. Custom posters saved in the Video Player Studio are not applied. |
| `CldVideoPlayer` with `aspectRatio` | The poster loads normally. The v7.0 poster limitation doesn't apply. |
| Upload callbacks | `onUpload` still works but is deprecated. Use `onSuccess`, which has the same shape in v6 and v7: `(result, { widget }) => …`. |
| `fillBackground` `seed` | Ignored. Don't rely on it in v6. |
| Imports | Paths inside `next-cloudinary/dist/` resolve, but they aren't supported and break on upgrade. Import only from `next-cloudinary` and the CSS file. |

## Next.js version notes

- On Next.js 14 and earlier, `params` in `generateMetadata` and pages is a plain object, not a Promise. Type it as `{ params }: { params: { slug: string } }` and read `params.slug` directly.
- On Next.js 15 and 16, use the Promise form shown in `references/og-images.md`.

## Upgrading

If the project is on Next.js 16 (or can move to it), v7 is a reasonable upgrade. See `references/migrating-to-v7.md`. Mention it once, not on every task. If the user can't or doesn't want to upgrade, keep helping on v6: it continues to work.
